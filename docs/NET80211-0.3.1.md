# MT7902 net80211 candidate 0.3.1

The supplied 0.3.0 capture confirms that the kext loaded, created en0 and scanned
the available APs. The Redmi join advanced from AUTH to ASSOC repeatedly, never
reached RUN/key exchange, then timed out. Later firmware recoveries failed with
EIO; the app continued requesting attempts against an unavailable radio. This
capture does not prove that the router or a password caused the failure.

This revision changes the integration at those boundaries:

- Preserve the live JOIN channel grant across authentication and association.
  Remove the premature firmware AUTH update; program firmware ASSOC after the
  association response, as in the existing MT7902 and mt76 station-event paths.
- Hold the grant through the RSN exchange until controlled-port authorization.
- Release an untouched passive-list epoch without a full firmware reload before
  the first join. Once peer/key/TX hardware was touched, require DMA quiescence
  before releasing that epoch; a software cancellation is insufficient.
- Reacquire driver ownership before recovery's initial register access. Quiesce
  partially bootstrapped DMA on failure, apply a five-second retry cooldown and
  stop after two consecutive failed bootstraps. Background list polls do not
  automatically recover a failed radio.
- Record fixed authentication/association response fields, submitted association
  requests/responses and RX-normalizer rejection counts. No EAPOL/key material is
  logged. A hardware test is needed to determine whether association responses
  were absent, rejected by normalization or rejected by the stack.

These are evidence-based corrections and a diagnostic candidate, not a confirmed
connection fix. Hardware loading and network traffic for 0.3.1 are unverified.
The 0.3.0 runtime failed the reported hardware connection test.

## Install and test

Keep the earlier working standalone kext/EFI as a recovery copy. Replace the
complete `EFI/OC/Kexts/itlmt7902.kext` bundle, keep its existing enabled OpenCore
entry, then reboot once. Use HeliPort-MT7902 2.1.5 (ABI v1). Firmware is embedded;
no separate Apple networking family or new boot argument is needed. Stage 3 is
the default; an explicit stage 1/2 override would still disable joining.

Verify the loaded build:

```sh
ioreg -r -c itlmt7902 -l -w0
```

Expect `port-version = 0.3.1-net80211` and `connection-engine = net80211`.
Try the phone hotspot first, then the two Ramos bands in the same boot. On
failure, collect the registry immediately using the included collector:

```sh
bash collect-logs.sh
```

The bridge currently advertises legacy a/b/g only. WPA3, required PMF,
HT/VHT/HE, QoS/aggregation and long-slot 2.4 GHz operation remain unsupported.
Supported channels are 1–11 and 36/40/44/48/149/153/157/161/165. An AP configured
to reject legacy clients can still refuse this candidate. Keep router settings
unchanged while collecting the first corrected-driver trace.

The package contains exact source archives, staged PAE modifications, original
GPL/BSD notices, firmware licenses and build evidence. The build uses the same
macOS 15 Intel runner and Xcode 16.4. Host sanitizer/fixture tests and a linked
kernel bundle are build validation, not over-the-air validation.
